# ADR-0010: M00 프로토타입 기반 해커톤 제출 슬라이스를 분리한다

- **상태**: 채택
- **결정일**: 2026-08-21
- **최종 검토**: 2026-08-21
- **관련 phase**: M00, M01, H00
- **관련 불변식**: INV-001~002, INV-004~006, INV-014~015, INV-017~020
- **관련 문서**: `HARNESS.md` §7~8, `PROGRESS.md`, `phases/H00_hackathon_submission_slice.md`

## 1. 맥락

OpenAI Game Builders 예선 접수 종료일 2026-08-26까지 5일이 남은 2026-08-21 시점에 M00과 M01만 완료됐고 M02~M11은 미착수다. 정규 순차 DoR·DoD를 완화하지 않고 전 범위를 5일 안에 완료하는 것은 불가능하다. M00 beta 5명은 규칙의 신선함과 이해 가능성을 확인했지만 단계 수, AXIS 고유 연출, 2D 표현 완성도를 우선 개선점으로 보고했다.

## 2. 결정

프로젝트 오너는 M00 공개 프로토타입과 M01 Pages artifact 기반의 별도 `H00 — Hackathon Submission Slice`를 2026-08-26까지 진행한다. H00은 `v0.1.0-hackathon` 제출용 프로토타입 lane이며 M02~M11, M10 QA, M11 release 또는 `v1.0.0` 완료를 의미하지 않는다.

## 3. 세부 계약

- 수정 범위는 `prototypes/rule-proof/**`, 기존 Pages artifact 조립·회귀, H00 문서·제출 자산으로 제한한다.
- PULSE, `Par=rank_GF2(D)`, `m00-seeded-v1`, 여섯 난도×크기 profile을 변경하지 않는다.
- 여섯 profile마다 서로 다른 고정 신호 3개 이상, 총 18개 이상의 재현 가능한 campaign signal을 제공하고 랜덤 새 신호 흐름을 유지한다.
- 행·열 선택 진행선, PULSE 교차점 충격, 완료 Signal Lock을 DOM/CSS 상태로 추가한다. 모션이 꺼져도 텍스트·형태·ARIA 상태는 유지한다.
- 새 게임 모드·규칙·대형 의존성·3D·백엔드·저장·Daily·Sprint·PWA를 추가하지 않는다.
- `src/domain/**`로 승격하거나 프로덕션 코어를 중복 구현하지 않는다. M02는 H00 후 원래 DoR에서 다시 시작한다.
- 제출 문구는 실제 H00 기능만 주장하고 Tutorial 6, Lab 48, Daily, Archive, Sprint, PWA를 구현 완료로 표시하지 않는다.
- 2026-08-23 이후 신규 기능·의존성을 동결하고 P0/P1 수정·문서·제출 자산만 허용한다.
- 후보 tag는 `v0.1.0-hackathon`, RC 표기는 `hackathon-2026-rc.N`을 사용한다.

## 4. 근거

정규 로드맵의 정확성 게이트를 낮추지 않으면서 심사 가능한 코어 재미와 제품 정체성을 공개 링크에서 보여주기 위해서다. 새 기술 스택보다 이미 검증된 프로토타입의 콘텐츠 가시성·축 인과·표현 완성도를 높이는 것이 5일 일정에서 효과와 회귀 위험의 균형이 가장 좋다.

## 5. 결과와 트레이드오프

### 이점

- M00에서 검증된 규칙과 200,967개 verifier 단언을 재사용한다.
- 사용자 피드백의 가장 직접적인 두 문제를 실제 플레이 화면에서 해결한다.
- M02~M11의 미완료 상태와 장기 v1 범위를 정직하게 보존한다.

### 비용·제약

- H00 코드는 폐기 가능한 프로토타입이며 생산 도메인 코어로 간주하지 않는다.
- 54개 정적 콘텐츠, Daily, 저장, 공유, PWA 등 장기 범위는 제출 뒤에도 남는다.
- public E4와 제출 패키지는 별도 commit·push와 실제 URL 검증 전에는 완료할 수 없다.

## 6. 검토한 대안

| 대안 | 장점 | 기각 또는 보류 이유 |
|---|---|---|
| M02~M11을 5일 내 완료로 선언 | 원래 roadmap과 이름이 단순함 | 순차 E3/E4·사람 게이트를 실행할 수 없어 허위 완료가 됨 |
| 3D 엔진 전환 | 표면적 시각 차별화 | 규칙 가독성·모바일·접근성·일정에 고위험이며 백서 비목표 |
| 기존 6단계 그대로 제출 | 회귀 위험 최소 | 단계 부족과 AXIS 표현 부족이라는 직접 피드백을 방치 |
| Daily/Sprint/PWA를 일부 급조 | 기능 수 증가 | 결정성·절대 시간·캐시 회귀 위험이 높고 정규 phase 계약을 우회 |

## 7. 검증·집행

- `phases/H00_hackathon_submission_slice.md`의 DoR·DoD와 allowlist로 범위를 감사한다.
- 기존 verifier `assertions>=200967`, browser smoke `assertions>=573`를 낮추지 않고 새 단언을 추가한다.
- campaign 18개 이상, profile별 중복 0, canonical solve와 URL 재현을 자동 검증한다.
- 320·360·390·960px, 키보드, reduced motion, Pages artifact를 검사한다.
- M02~M11 상태는 H00 완료와 무관하게 미시작으로 유지한다.

## 8. 변경 조건

PULSE·Par·generator version·생산 경계를 바꾸거나 새 모드·의존성을 추가해야 하면 H00을 즉시 중단하고 별도 ADR과 오너 승인을 받는다. 2026-08-23 이후 기능 범위 확대는 허용하지 않는다.
