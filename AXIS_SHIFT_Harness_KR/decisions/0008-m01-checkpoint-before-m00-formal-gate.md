# ADR-0008: M00 formal gate 전에 M01 제한 체크포인트를 착수한다

- **상태**: 채택
- **결정일**: 2026-08-14
- **최종 검토**: 2026-08-14
- **관련 phase**: M00, M01
- **관련 불변식**: INV-001~003, INV-014, INV-017~019
- **관련 문서**: `PROGRESS.md`, `phases/M00_rule_proof.md`, `phases/M01_scaffolding.md`

## 1. 맥락

M00의 규칙 구현·자동 E2와 공개 플레이 체크포인트는 완료됐지만 formal Easy n≥5 E1과 DOD-02~07은 참가자·개별 기록 지표를 확보할 수 있는 출시 직전 playable beta까지 연기돼 있다. 원래 phase 계약은 이 사람 대상 게이트 전 프로덕션 스캐폴딩을 금지했으나, beta 자체를 만들 기반이 필요해 순환 대기가 생겼다.

## 2. 결정

프로젝트 오너는 2026-08-14 M00 사람 대상 gate 전에도 M01 Production Scaffolding 체크포인트 착수를 명시적으로 승인했다. 이는 M00을 통과·면제 처리하는 결정이 아니며, M01 작업을 도구 체인·모듈 경계·Hash Router·CI·최소 AppShell에 한정하는 선행 착수 예외다.

## 3. 세부 계약

- M00 DOD-02~07은 출시 직전 beta 증거가 기록될 때까지 미완료로 유지한다.
- M01에서는 퍼즐 수학, 세션 규칙, 콘텐츠, 대규모 UI를 구현하지 않는다.
- M01 DoD는 완화하지 않으며 각 명령과 경계 실패 증거를 그대로 요구한다.
- 이 예외는 M02 착수, 릴리스 승인 또는 M00 Scope Lock 완료를 자동 승인하지 않는다.
- 최종 공개 라이선스 결정 전 package는 `private: true`, `UNLICENSED`로 유지한다.

## 4. 근거

사람 대상 gate를 실제 beta까지 연기한 상태에서 재현 가능한 beta 기반을 먼저 만들되, 규칙·난도 판단을 자동 테스트로 대체하지 않기 위해서다. 제한 범위와 미완료 gate를 동시에 명시하면 초기 금지의 목적을 보존하면서 순환 대기를 해소한다.

## 5. 결과와 트레이드오프

### 이점

- beta 제작에 필요한 재현 설치·CI·경계 기반을 먼저 확보한다.
- M00 사람 판단과 M01 공학 품질을 서로 다른 증거로 유지한다.
- 프로토타입 코드를 성급하게 생산 도메인 코어로 승격하지 않는다.

### 비용·제약

- 한동안 M00과 M01 상태를 병행 추적해야 한다.
- M01 완료만으로 M02 또는 릴리스 준비를 주장할 수 없다.
- beta에서 M00 gate가 실패하면 M01 기반 위에서 규칙/UI 재작업이 생길 수 있다.

## 6. 검토한 대안

| 대안 | 장점 | 기각 또는 보류 이유 |
|---|---|---|
| M00 formal E1까지 모든 생산 작업 중단 | 원래 순서가 단순함 | playable beta 기반이 없어 참가자·기록 gate 준비가 지연됨 |
| 자동 E2를 M00 사람 gate로 대체 | 즉시 phase 완료 가능 | 사람의 규칙 이해·재미를 증명하지 못해 DOD와 충돌 |
| M01 전체 제품 구현까지 선행 | 일정상 빠름 | 수학·UI 범위가 M00 판단을 앞질러 초기 금지 목적을 훼손 |

## 7. 검증·집행

- M00 phase와 PROGRESS에서 DOD-02~07 미체크를 유지한다.
- M01 변경 범위를 phase 산출물과 git diff로 감사한다.
- M01 DoD의 설치·lint·type·test·build·경계·route·CI 증거를 별도로 기록한다.
- `docs/CODEX_COLLABORATION.md`에서 사람의 예외 승인과 Codex 구현을 구분한다.

## 8. 변경 조건

M00 formal beta 결과가 규칙 또는 공개 범위 변경을 요구하거나, M01을 넘어 M02 선행 착수가 필요할 때 프로젝트 오너 승인과 후속 ADR로 재검토한다.
