# ADR-0013: 해커톤 lane을 종료하고 일반 공개 출시 로드맵으로 복귀한다

- **상태**: 채택
- **결정일**: 2026-08-30
- **최종 검토**: 2026-08-30
- **관련 phase**: H00, M06~M11
- **관련 불변식**: INV-001~002, INV-011, INV-013~020
- **관련 문서**: `PROGRESS.md`, `HARNESS.md`, `README.md`, `phases/M10_integration_qa_deployment.md`, `phases/M11_release_submission.md`, `docs/REQUIREMENTS_TRACEABILITY.md`, `docs/RELEASE_CHECKLIST.md`, `docs/RELEASE_NOTES.md`

## 1. 맥락

AXIS//SHIFT의 H00 `v0.1.0-hackathon`은 OpenAI Game Builders 예선에 제출됐으나 본선 진출 대상으로 선정되지 않았다. H00은 제한된 일정에서 규칙과 공개 링크를 검증하기 위한 별도 lane이었고, 정규 M02~M11 제품 로드맵의 완료를 뜻하지 않는다. 프로젝트 오너는 이제 행사 심사나 제출 마감이 아니라 일반 사용자가 안정적으로 플레이할 수 있는 웹 게임의 정상 배포·런칭을 목표로 정규 마일스톤을 완성하기로 했다.

## 2. 결정

H00 해커톤 lane은 완료된 역사 기록으로 동결하고, 현재 개발의 단일 목표를 **정규 M06~M11을 순서대로 통과한 일반 공개 출시**로 전환한다. M10은 production release candidate의 통합 QA·배포를, M11은 행사 제출이 아닌 release freeze·공개 런칭·운영 인계를 담당한다.

## 3. 세부 계약

- H00 tag, 제출 자산, CI·Pages 증거와 결과는 수정하거나 정규 제품 완료 증거로 재분류하지 않는다.
- 해커톤 마감·심사 필드·3분 시연·제출 자산은 더 이상 정규 scope나 우선순위를 결정하지 않는다.
- M06 DOD-03 신규 사용자 E1을 포함한 각 phase의 미완료 DoR·DoD는 완화하지 않고 M06 → M07 → M08 → M09 → M10 → M11 순서를 유지한다.
- 일반 공개 출시는 로그인 없는 production URL, 핵심 모드, 저장·오프라인·공유, 접근성, 개인정보·자산 권리, P0/P1 0건과 rollback 가능한 배포를 요구한다.
- 기존 H00 공유 URL은 M11에서 별도 폐기 승인이 있기 전까지 호환 경로로 유지한다.
- release version, 출시일, 최종 도메인, 공개 라이선스는 프로젝트 오너 결정 전까지 `TBD`이며 임의로 확정하지 않는다.
- 백엔드, 계정, 분석, 광고, 수익화, 앱 스토어 패키징은 이 결정만으로 scope에 추가하지 않는다.
- 마일스톤 단위 commit·push와 fixed-SHA 증거 계약은 기존 Git 계약을 유지한다.

## 4. 근거

행사 일정이 사라진 뒤에도 제출용 vertical slice를 제품 목표로 유지하면 미완료 Daily·Sprint·PWA·접근성·QA보다 홍보 자산을 우선하는 왜곡이 생긴다. 검증된 정규 로드맵으로 복귀하면 기능 수보다 플레이 가능성, 저장 안전성, 실제 기기 접근성, 배포 재현성과 운영 복구를 출시 기준으로 삼을 수 있다.

## 5. 결과와 트레이드오프

### 이점

- 해커톤 결과와 무관하게 장기 제품 품질 기준을 유지한다.
- H00의 공개 링크·피드백·기술 증거는 회귀 기준과 역사 자료로 계속 활용한다.
- 출시일 압박으로 사람 대상·실기기·접근성 게이트를 생략하지 않는다.

### 비용·제약

- 출시 버전과 일정은 남은 사람 대상·통합 QA 증거가 확보될 때까지 확정할 수 없다.
- M07~M09 기능과 M10 수동 검증이 끝나기 전에는 정식 출시 완료를 주장할 수 없다.
- H00 호환 경로를 유지하는 동안 Pages artifact와 회귀 테스트의 복잡성이 남는다.

## 6. 검토한 대안

| 대안 | 장점 | 기각 또는 보류 이유 |
|---|---|---|
| H00을 최종 제품으로 유지 | 즉시 공개 상태를 유지하기 쉬움 | 저장·Tutorial/Lab·Daily·공유·PWA와 정규 QA가 빠져 일반 출시 기준을 충족하지 못함 |
| 해커톤 결과 후 프로젝트 종료 | 추가 비용 없음 | 이미 검증된 규칙·콘텐츠·제품 기반과 오너의 지속 개발 의도에 맞지 않음 |
| 새 엔진·3D 게임으로 전면 전환 | 시각적 차별화를 다시 시도할 수 있음 | 현재 코어·접근성·콘텐츠 검증을 폐기하며 일반 출시 목표와 무관한 대형 scope 변경임 |
| M06 사람 게이트를 건너뛰고 후속 기능 우선 | 구현 속도가 빨라 보임 | 첫 사용자 학습 실효를 확인하지 못해 제품 출시 위험을 뒤로 미룸 |

## 7. 검증·집행

- `PROGRESS.md`는 현재 목표를 일반 공개 출시로 표시하고 H00 결과를 역사 항목으로 분리한다.
- M10은 fixed-SHA CI, 실제 production URL, 브라우저·실기기·접근성·성능·보안·rollback 증거를 요구한다.
- M11은 release manifest, tag·artifact·URL 일치, 문서·권리·개인정보, launch smoke와 운영 인계를 요구한다.
- `docs/RELEASE_CHECKLIST.md`와 공개 README는 해커톤 제출 템플릿을 정규 출시 게이트로 사용하지 않는다.
- 각 phase 완료 전 `PROGRESS.md`와 해당 phase 문서에 실제 명령·핵심 출력을 기록한다.

## 8. 변경 조건

배포 플랫폼, 수익 모델, 계정·온라인 서비스, 앱 스토어 출시 또는 코어 게임 규칙을 추가하려면 별도 ADR과 프로젝트 오너 승인이 필요하다. 출시 버전·일정·도메인·라이선스는 관련 DoR 시점에 별도로 결정하고 이 ADR의 일반 공개 출시 품질 게이트를 낮추지 않는다.
